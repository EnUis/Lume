# Automatic artwork and descriptions

The background worker automatically fills missing posters, banners and descriptions for published movies, series and live channels, and checks verified English display titles even when artwork and descriptions are already present. It checks verified playable titles first, then a small number of other published entries. Titles awaiting publication review, explicit adult/XXX provider labels, and administrator-locked metadata are excluded. Existing nonempty artwork/text, years, stream languages, playback sources and progress are preserved.

English names come only from an explicitly English Wikidata label, an English-localized TMDB record, or a licensed provider's `englishTitle`. There is no literal machine translation or fuzzy identity merge. Exact original names/aliases, content type and known release years must agree; an existing provider identifier can bind a changed localized name, but still must agree with type/year and other saved identifiers. Original display names and confirmed localized labels become searchable `title_aliases`. A saved or TVmaze-confirmed IMDb ID can resolve the corresponding Wikidata item through a bounded exact-property search, followed by claim/type/year verification; a missing local alias no longer blocks that identity. An administrator metadata lock or concurrent identity edit prevents any automatic rename. A conflicting provider ID remains unresolved for administrator review. Successful lookup records include enrichment-policy version 3 and the updated display identity, avoiding a repeated rename/lookup cycle.

No metadata key is required for the default providers:

- **Series:** the official [TVmaze search and show images API](https://www.tvmaze.com/api) supplies show posters, backgrounds/banners, summaries and genres. Matching requires an exact normalized name and the known premiere year, or an already bound show ID with matching year. Unknown-year names with multiple exact shows are left unresolved. TVmaze's unlocalized name is not treated as proof of an English translation. TVmaze is credited with a show link; its data is [CC BY-SA](https://www.tvmaze.com/api#licensing).
- **Live channels:** Wikidata English labels are accepted only for a uniquely matched television channel, station or network (including validated subclasses). A same-named film, series, person or place is rejected. Channel logos use the structured P154 statement. TMDB and TVmaze movie/series APIs are never used as channel identity sources.
- **Films and series fallback:** the official [Wikidata Action API](https://www.wikidata.org/wiki/Wikidata:Data_access) searches labels/aliases and validates film/series class ancestry and release-year claims. The matched item's Wikipedia sitelink supplies a concise article introduction and lead artwork through official [TextExtracts](https://www.mediawiki.org/wiki/Extension:TextExtracts) and [PageImages](https://www.mediawiki.org/wiki/Extension:PageImages) APIs. The returned article must have the same Wikidata identity. Artwork is tied to that confirmed article and its image-info record, with source, artist and image-rights attribution. A reusable Commons film-poster statement (P3383) is a fallback. General P18 photos are not treated as posters.

Descriptions contain at most 140 words. These are provider excerpts or actual Wikidata descriptions; the application does not generate fictional summaries, guess from fuzzy search ranking, or collect image-search thumbnails. Missing/ambiguous items retain their existing artwork fallback. Translated labels can match aliases, but unknown names and remakes may require manual metadata or an explicit provider identifier.

Repeated season labels and episode/provider tags are removed from lookup names and aliases before provider requests. Arabic and other non-Latin names use the corresponding script-language search and requested label/alias languages. Searches consider at most three saved names; metadata candidates and provider calls remain bounded and cached. Wikimedia landscape artwork is accepted only from the confirmed work's structured P18 image with landscape dimensions and explicit reusable Commons rights. A portrait poster is never saved as a fabricated backdrop; the frontend may display the confirmed poster when no landscape image is supplied.

Wikidata structured data is CC0. Wikipedia excerpts are CC BY-SA 4.0 and include article attribution. Individual images have their own rights: a Wikipedia article poster can be marked non-free/fair use, and linking its source does not grant a commercial reuse license. Deployments should use an appropriate licensed provider for artwork requiring broader distribution rights. The per-title attribution records its actual image source and license instead of claiming every image is freely licensed.

## Optional configured providers

The preferred configured adapter uses `METADATA_PROVIDER_URL` and `METADATA_API_KEY`. The URL must be HTTPS without embedded credentials. The server sends only canonical title/year/type query fields and a bearer header; it does not send playlist URLs, account information or stream credentials. Its JSON contract is:

```json
{"id":"provider-item-id","name":"Exact or known-alias title","englishTitle":"Verified English release title","type":"movie","year":2009,"synopsis":"Sourced description","poster":"https://licensed-cdn.example/poster.jpg","backdrop":"https://licensed-cdn.example/background.jpg","genres":["Drama"],"cast":["Actor"],"director":"Director","attribution":"Required provider credit"}
```

`name`/`title`, `type`, and a matching known `year` are required identity evidence. Other metadata fields are optional. An older service returning only images/text without identity proof is left unresolved rather than silently assigning a potentially wrong title.

Alternatively, configure `TMDB_READ_ACCESS_TOKEN` (preferred bearer) or `TMDB_API_KEY` for the official TMDB movie/TV search and artwork CDN. Adult search results are excluded. Exact title/original title/alias and known release year must match, and unknown-year paginated results remain unresolved. If an English search has no exact match, a bounded second search in the imported name’s language can verify the localized title before fetching the same provider ID in English. Existing IMDb identities require corroborating external-ID details. Follow the [TMDB license and attribution requirements](https://developer.themoviedb.org/docs/faq), including the approved logo and the notice: “This product uses the TMDB API but is not endorsed or certified by TMDB.” Commercial use requires an appropriate provider agreement. Licensed-adapter configuration takes priority over TMDB; otherwise the public providers are used.

## Scheduling, cache and recovery

`METADATA_AUTO_ENRICH=true` is the default; `false` stops automatic scheduling/lookups. `METADATA_LANGUAGE=en` controls provider language where supported. `METADATA_USER_AGENT` should identify the app and an operator contact for Wikimedia etiquette. Keys remain server-side.

Each minute, a worker queues at most 20 eligible candidates, including at most 5 without verified playable media. Visible foreign-script names receive priority within the featured-title ordering; old enrichment-policy matches/no-matches are revisited once. Active jobs are deduplicated, and verified candidates receive queue priority without bypassing attempted-job backoff. Default three-consumer workers reserve a metadata lane alongside imports and health verification. Importing a large playlist does not enqueue every title for immediate online lookup.

HTTP JSON responses are cached for 24 hours in the database. Matched or unresolved lookups have a seven-day cooldown; changing the saved name/type/year or provider configuration permits a fresh explicit lookup. Policy upgrades revisit previous matches/no-matches without repeatedly bypassing current-version cooldowns. Provider request reservations are shared across processes: TVmaze requests are spaced by at least 600ms; combined Wikimedia requests by at least 1.1s. Wikimedia requests use `maxlag=5`. HTTP 429/503 or maxlag sets a durable provider cooldown honoring Retry-After within bounded delays. Network/application failures retain durable job retries and a scheduler cooldown. Each request has a 15-second deadline and a 2MiB response cap. Expired cached responses are deleted in batches.

The supported queue-only backfill command is:

```sh
npm run backfill-metadata -- --limit 20 --background 5
```

`--limit` accepts 1–100; `--background` accepts 0–20. `--force` queues eligible missing titles or unchecked English display names despite prior lookup cooldown. Repeat `--title-id ID` to restrict a repair to up to 100 selected existing titles. This enqueues a bounded batch; the worker performs lookups separately. Use it after adding provider credentials or upgrading the enrichment policy to revisit gaps. It never replaces populated artwork/text or overrides administrator locks. Stopped/interrupted jobs retain the normal durable lease and retry recovery behavior.

Provider lookups run outside catalog transactions. Before applying a result, the worker rechecks the saved name/type/year and metadata lock and reserves the unique provider identity transactionally. A concurrent manual edit, rename, merge or competing identity match cannot cause stale artwork to overwrite the current title.

Channel type identifiers follow [Wikidata television channel](https://www.wikidata.org/wiki/Q2001305), [television station](https://www.wikidata.org/wiki/Q1616075) and [television network](https://www.wikidata.org/wiki/Q1254874). IMDb resolution uses the [Wikidata exact P345 statement search](https://www.wikidata.org/wiki/Wikidata:Requests_for_permissions/Bot/Tmdbzhbot) and verifies the returned claim independently. Free providers do not cover every regional title; unresolved names retain a clean original display name until a verified English label or administrator edit is available.
