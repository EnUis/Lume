# Lume architecture

Next.js App Router with React/TypeScript; Node server API handlers; PostgreSQL for deployment, built-in SQLite for a zero-infrastructure local development option. Both use the same normalized relational model. Durable database-backed job leases and retries remove the need for a separate Redis dependency. Workers run independently of web requests. No public stream proxy.

Public discovery requires a published title and at least one enabled, present source with healthy status and no playback block; a linked playlist must also be enabled. Degraded, unknown, unavailable and browser-blocked sources stay excluded. One failed health check makes a source unavailable immediately. A browser playback failure sets a persistent block that background container checks cannot clear, including checks already in flight. One healthy, unblocked alternative keeps a movie available. Series availability is computed per episode. A failed playlist sync preserves the previous imported snapshot and progress.

API JSON contracts use camelCase and the shared lib/types.ts definitions. GET /api/catalog?q=&type=&genre=&year=&page= returns {titles,total,genres}. GET /api/discovery returns database-backed featured, recent, trending, popularMovies and popularSeries feeds; popularity requires recorded viewing. Public discovery responses use no-store. GET /api/collection?ids= retrieves up to 100 available public title records for saved browser collections without relying on discovery pagination. GET /api/titles/:id returns {title,related}. GET /api/playback/:id?episodeId= returns {sources} with playback URLs, language, and opaque 15-minute playbackAttemptToken credentials only for available sources. POST /api/playback/failure and /api/playback/success accept {sourceId,playbackAttemptToken}. Failure blocks the source immediately; a new successful playback attempt can restore it. POST /api/playback/attempt accepts {sourceId,playbackAttemptToken?} and returns {source} for an explicit retry or reporting-token renewal. Prior credentials retain URL binding when expired; obsolete URLs cannot report a current source as recovered. The player records success only after playing and time advancement, retains its loaded media URL during token renewal, and refreshes browsing availability after failures/recovery.

Reporting credentials bind the source, original URL hash, request identity and latest block revision. A reported failure blocks all source references with the identical URL hash; each reference still needs its own fresh attempt to recover. Explicit retry sources retain unavailable health and carry playbackRetry:true until advancing browser playback is reported with a fresh token. Issuing a token alone never republishes a source. Saving an unchanged source URL preserves its block; an actual URL-hash change resets verification and invalidates old tokens, while inheriting any existing block on that replacement URL. Blocked sources have no automatic recovery expiry.

Explicit language metadata and recognized title tags preserve English, German, Turkish and other source versions under one matching movie or series. Conflicting identities and ambiguous undated copies remain separate for review. Merges retain old IDs in title_redirects; details, playback, collections and registered progress/list writes resolve them to the surviving title. User records and source IDs survive merging. Existing internal luma database paths, cookies and browser-storage keys remain unchanged. For older imports, stop workers and run npm run repair-languages once with a database/encryption-key backup; see docs/BACKEND.md for the SQLite backup and PostgreSQL requirements.

GET /api/auth/me -> {user:null|User}; POST /api/auth/register {name,email,password}; POST /api/auth/login {email,password}; POST /api/auth/logout. HttpOnly session cookies, same-origin mutation checks. GET /api/progress -> {progress:Progress[]}; POST /api/progress {titleId,episodeId,position,duration}; POST /api/progress/migrate {progress:Progress[]}, explicitly invoked with consent. GET /api/list -> {ids:string[]}; POST /api/list {titleId}; DELETE /api/list?titleId=.

Admin API: GET /api/admin/overview -> {stats,playlists,jobs,reviews,audit,worker}; playlist records include import stages and parsed, pending, playable, unavailable and visible counts. GET/POST /api/admin/playlists; PATCH/DELETE /api/admin/playlists/:id; POST /api/admin/playlists/:id/sync; GET /api/admin/catalog; PATCH /api/admin/titles/:id; POST /api/admin/titles/merge {fromId,toId}; POST /api/admin/sources/:id/check; PATCH/DELETE /api/admin/sources/:id; POST /api/admin/sources {titleId,episodeId?,name,url,priority?}; POST /api/admin/sources/:id/split {name,year?}; POST /api/admin/reviews/:id {action,targetId?}. POST /api/admin/playlists accepts {name,url?,content?,intervalHours,authorized:true}. Uploaded files are parsed client-side as text and sent as content. /api/health for deployment readiness.

Seed catalog contains actual licensed Blender open films. Import through the real pipeline, verify before publish, label as sample content and retain credits. No invented streaming availability or fabricated film identities.
