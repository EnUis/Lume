# Public discovery feeds

`GET /api/discovery` returns `{ featured, trending, recent, popularMovies, popularSeries }`, each containing at most 12 public title records. Only published titles with an enabled, present, healthy and playback-unblocked source are eligible; linked playlists must also be enabled. Degraded, unknown, unavailable and browser-blocked sources stay excluded. One failed health check immediately removes that source from eligibility. A browser failure creates a persistent block that background checks cannot clear. Another qualifying source keeps the title visible. A series remains eligible when at least one episode is playable.

Default discovery, catalog and search contain movies and TV shows. Live TV is a separate category: `GET /api/catalog?type=live` browses and searches verified channels, with channel-only genres. Published channels use the same availability checks and can be opened through `/api/titles/:id` and `/api/playback/:id`, including saved title redirects. Lists, favorites, `/api/library` and explicit `/api/collection?ids=...` support live bookmarks; unavailable saved entries remain in account metadata with `available:false`. Live viewing creates no resume position or watch history and never affects movie/series discovery rankings.

Explicit language versions, including English, German and Turkish, share one matching catalog title while retaining separate source records and a player language selector. Ambiguous remakes and conflicting identities stay in review. Consolidated title IDs resolve through stored redirects, preserving old detail links, saved collections and user records; existing internal `luma` storage identifiers remain compatible. Older installations can consolidate prior imports with the documented `npm run repair-languages` procedure after stopping workers and backing up the database and encryption key.

Featured titles use the administrator's featured flag. Recent titles sort by their database creation time. Trending ranks distinct registered viewers with positive viewing progress updated during the preceding seven days. Popular Movies and Popular Series rank distinct registered viewers across all recorded history, within their respective content types. Watching several episodes or repeated history entries counts one viewer per title. Ranking ties use most recent viewing activity, then title creation time and a stable identifier.

An empty viewing history produces empty trending and popularity feeds. The homepage should omit those categories until genuine activity exists. Guest history stays on the guest's device and never contributes to these aggregate rankings. The endpoint returns title metadata only, with no viewer identities or per-viewer activity.

Catalog and discovery responses use `no-store`, and the player refreshes browsing results after a failure or recovery. A reported failure blocks every source reference with the identical URL hash, including versions in other playlists or languages. A blocked source returns only through an explicit authorized retry; it remains unavailable until advancing browser playback is reported with a fresh token for its current URL and block revision. Recovery is source-specific. Saving the same URL, adding another reference to a blocked URL, or a successful server probe cannot republish it. Feed limits bound returned results; indexes on recent history and title/viewer identity support aggregation, but production catalog sizes and PostgreSQL execution plans still require deployment-specific performance checks.
